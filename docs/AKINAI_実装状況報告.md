## 1. 全体像 — 何を作ったか

保険業法（施行規則234条の2・意向把握義務）に準拠した、自動車保険の満期更新の意向把握・来店誘導システム。**入口3つ（電話発信 OB／電話着信 IB／チャット CB）、意向把握コアは1つ（S3〜S7共通）**の構成。

```
【OB】発信エージェント          【IB】着信エージェント        【CB】チャットボット
 050-1725-0049 から架電          050-1725-0049 に着信          SMS→マジックリンク
      │                              │                            │
  OB1 本人確認                   IB1 録音告知(冒頭必須)        CB1 トークン検証
      │                          IB3 本人認証(名前+生年月日)        │
      │                          IB4 用件4択 ──┬─ ③事故 → E-ACC 即・人へ転送
      │                              │         └─ ④その他 → H-ESC 人へ
      └──────────┬──────────────────┘                            │
                 ▼                                               │
        S3 意向確認【3択】 ←─────────────────────────────────────┘
        S4 生活変化 → S5 追加オプション(Aのみ) → S6 来店日時 → S7 証跡確定
                 │
        A → R1 確認メール ／ B・C → R2 面談ご案内メール（自動送信）
```

**設計原則の実装状況**: AIは募集をしない（推奨・比較・見積り禁止をプロンプトで強制）／発話は事前定義のみ（static_text固定）／全分岐をタイムスタンプ付きで記録（append-only証跡）／事故はAIが扱わず即・人へ転送 — すべて実装済み。

## 3. チャットボット（CB）

**URL**: `https://www.callcenter-ai.me/akinai/chat?token=<マジックリンク>`

- **入口はマジックリンク経由のみ**（v0.3確定事項）。SMSに記載されたURLからのみ到達可能
- タップで**認証不要で開始**（トークンが顧客×通話IDに紐付き済みのため）。冒頭に「記録を保存する」旨を表示
- **S3以降は電話と完全に同一の分岐・同一の選択肢文言**を選択肢ボタンUIで実施（テキスト自由入力なし、S6日時はカレンダー入力）→ 誤認識が構造的に発生しない
- **CB2 失効時導線**: 期限切れ・使用済みリンクは契約情報を一切表示せず「再送を依頼する」ボタンのみ → 担当者へメール通知（人が確認して再送）
- **CB-ESC**: 全画面に「AIではなく担当者に相談する」を常設 → 押すと折り返しキュー登録（証跡: customer_request）＋担当者へメール通知してチャット終了

**マジックリンク仕様**（定義書要件を全て充足）: 暗号論的乱数（24バイト）／**7日有効**／**1回で無効化**（未完了セッションのみ再開可）／customer_id×call_id紐付け／発行・送信・タップ日時を全て記録。

## 4. SMS連携（3モード・特定電子メール法対応）

**API**: `POST /api/akinai/sms`（認可: ダッシュボードログイン or `x-akinai-key` ヘッダー）

| モード | トリガー | 状態 |
|---|---|---|
| F1-a | 架電→不在・拒否→SMS | ✅ webhookから全自動 |
| F1-b | 架電のn時間前の予告SMS | ✅ API手動送信（自動スケジューラは未実装） |
| F1-c | **SMSのみで完結（架電しない）** | ✅ 通話ゼロでS3〜S7→後確まで一周可能 |

**特定電子メール法対応**（定義書がv0.3まで未実装と指摘していた部分）:

- SMS本文に**送信者表示**「【AKINAI／Data Agent AI株式会社】」を明記
- 本文に**配信停止URL**（オプトアウト導線）を必ず記載 → `/akinai/optout` ページで停止手続き
- **サプレッションリスト**（`akinai_suppression`テーブル）**照合なしの送信は構造的に不可能**（送信関数内部で強制照合、拒否済み番号は送信されず409）

## 5. ナレッジベース（専門知識）

**Retell KB**: `knowledge_base_35a9b62f3ba13f11`「AKINAI 自動車保険 基礎知識 v1」— OB/IB両エージェントに接続済み。

**登録済みの6項目**:

1. **自動車保険の基本構成** — 対人・対物・人身傷害・搭乗者傷害・車両保険、自賠責と任意保険の違い
2. **等級制度** — 1〜20等級、3等級ダウン事故、事故有係数、等級継承、中断証明書
3. **満期・更新の用語** — 満期日、更新の3方式、猶予期間、証券番号
4. **代表的な特約** — 弁護士費用・ドラレコ・ファミリーバイク・個人賠償・運転者限定・年齢条件
5. **生活変化と見直しの関係** — 車両入替、使用目的変更、家族の免許取得、住所・名義変更
6. **事故対応の基本** — AIは対応せず人へ引き継ぐ前提の参考知識

**ガードレール**（ロ方式との両立・プロンプトで強制）: 知識の用途は「お客様の言葉の理解」と「用語の一般的な意味を1〜2文で回答」のみ。**商品比較・推奨・個別契約の判断・見積り・支払可否には使用禁止** → 聞かれたら「詳しくはご来店時に担当者よりご説明いたします」の定型文に戻る。

**追加登録**: 代理店の商材リスト・約款・FAQなどの実資料（PDF/URL/テキスト）をもらえれば同じKBに追加可能。

## 6. 証跡（コンプライアンスの核）

**保存先**: Supabase 東京リージョン（= 国内データ保管要件に適合）

| テーブル | 内容 |
|---|---|
| `akinai_evidence` | **append-only分岐ログ**。全選択を連番+タイムスタンプ+提示選択肢+選択原文で記録。**UPDATE/DELETEはDBトリガーで拒否**（service_role権限でも改竄不可能なことを検証済み） |
| `akinai_sessions` | セッション集約。入口(OB/IB/CB)・方向・認証(方式/回数/結果)・意向・生活変化・来店日時・エスカレーション・SMSモード・**content_hash(sha256)**・TSAトークン・後確種別 |
| `akinai_magic_links` | リンク発行・送信・タップ・失効・オプトアウトの全日時 |
| `akinai_suppression` | SMS受信拒否リスト |

S7完了時に全証跡の**sha256ハッシュを確定**し、TSAトークン（デモ用擬似。本番は認定TSA/RFC3161に差し替え）を付与。`scenario_version`（現在v0.4）を全レコードに記録し「どの版で意向を取得したか」を証明可能。

**後確（R1/R2）**: S3の選択に応じて自動メール送信（Resend・認証済みドメイン）。A→R1確認メール（応答内容を表形式で記載）／B・C→R2面談ご案内メール。送信自体も証跡ノードとして記録。エスカレーション時は人が対応するため送信しない。
